# 화폐 분리 — 방 포인트와 낚시 골드

> 결정: **방 포인트는 낚시에 쓸 수 있지만, 낚시에서 번 것은 방 포인트로 바꿀 수 없다.** 낚시 안에서는 별도 화폐를 쓴다.
> 코드는 고치지 않았다.

## 왜 나누나

- 지금은 낚시 수익이 **방 포인트로 바로 들어간다**(`db.grant_points` 16곳). 낚시 경제가 커지면 방 포인트가 같이 불어나서, 방 포인트를 쓰는 다른 봇 기능(버닝타임·의회·차트 등)의 물가까지 흔들린다.
- 나누면 **낚시 경제는 낚시 안에서만** 오르내리고, 방 경제는 보호된다.
- 시즌이 바뀔 때 **낚시 화폐만 따로** 정리할 수 있다(방 포인트는 그대로).

## ⭐ 단순화 버전 (추천)

**규칙 한 줄: "낚시에서는 🪙골드를 쓴다. 방 포인트는 골드로 바꿀 수 있지만, 골드는 포인트로 못 바꾼다."**

| | 방 포인트 (지금 그대로) | 🪙 골드 (낚시 전용, 새로) |
|---|---|---|
| 버는 곳 | 방 채팅 등 지금 방 기능 | **낚시 수익 전부** (낚시, 그물, 의뢰, 일감, NPC 전리품, 운임 …) |
| 쓰는 곳 | 방 기능 + **골드로 환전** | **낚시 안의 모든 것** (강화, 상점, 부적, 수리, 확성기, 도박선, 경매, 신화 상점 …) |
| 바꾸기 | 포인트 → 골드 ✅ | 골드 → 포인트 ❌ |

### 환전 — `1환전 [포인트]` (새 명령 1개)

- 개인톡에서 `1환전 10000` → 방 포인트 10,000 → 🪙 골드 10,000.
- **한 방향만.** 반대로는 안 된다.
- **명령으로 직접** 바꾼다. 살 때 골드가 모자라면 방 포인트에서 자동으로 빼는 방식은 쓰지 않는다 — 모르는 사이에 방 포인트가 줄면 기분 나쁘다.
- **하루 환전 한도**를 둔다(예: 하루 낚시 평균 수익 정도). 방 포인트가 많은 사람이 낚시 성장을 돈으로 바로 사 버리지 않게.

### 화면에서 보이는 것

- 낚시 결과: `+1,200🪙` (지금 `+1,200P` 자리)
- `1포인트`(개인톡): 한 번에 둘 다 → `💰 방 포인트 52,300P · 🪙 골드 18,400` (새 명령 없음)
- 낚시 랭킹·약탈왕·일보: 전부 골드 기준
- 상점·강화 가격: 전부 골드

> 플레이어가 낚시 안에서 보는 화폐는 여전히 **하나(골드)**다. 새로 아는 것은 "방 포인트로 골드를 살 수 있다"는 것 하나뿐. 그래서 1순위 기준의 "새 화폐 금지"에서 예외로 둔다.

## 바뀌는 곳 (코드 반영할 때 체크리스트)

### 낚시 안 (`fishing.py`)
- `db.grant_points` 16곳 → 골드 지급으로 (낚시 수익, 의뢰, 그물, 비서 장부, 신화 비서 이자, 항구 이용료, 운영자 지급 등)
- `db.spend_points` 7곳 → 골드 차감으로 (강화, 개조, 보호막, 상점, 부적, 수리, 확성기 등)
- `db.points_take` 4곳 → (약탈 개편 후 대부분 사라짐) 남는 곳은 골드로
- `config.POINT_NAME` 135곳 → 낚시 화면은 `config.FISH_GOLD_NAME`("🪙" 또는 "골드")
- 비서 신화 "이자: 잔액의 n%" → **골드 잔액** 기준
- 신화 상점의 "💰 포인트" 상품 → "🪙 골드"
- 주인 이벤트·운영자 지급의 `points` 종류 → 골드

### 낚시와 붙어 있는 다른 모듈
| 모듈 | 할 일 |
|---|---|
| `casino.py` (도박선 슬롯·경주·야구·룰렛) | 판돈·상금 골드로 |
| `auction.py` (낚시 경매) | 입찰·낙찰 골드로 |
| `shop.py` (낚시 상점이 쓰는 부분) | 가격 골드로 |
| `points.py` (`1포인트`) | 개인톡에서 골드도 같이 보여 주기 + `1환전` |
| `charts.py` · `scatter` 등 | 낚시 수익을 그리는 곳이 있으면 골드 기준으로 |

### DB
- 사람마다 골드 잔액 한 칸 + 골드 내역 표(지금 포인트 내역과 같은 모양, 사유 포함). 경제 측정(`season2-plan.md` 2)도 이 내역으로.

## 시즌 1 → 시즌 2 넘어갈 때

- **방 포인트는 전부 정산 후 0으로 초기화.** 남은 방 포인트는 구간별 비율로 **시즌 2 시작 골드**가 된다(`season1-rewards.md` "방 포인트 정산").
- 시즌 2의 방 포인트는 0에서 다시 모이고, 모인 만큼 `1환전`으로 골드로 바꿀 수 있다(한도 그대로).
- 시즌이 바뀔 때마다 **골드도 초기화**한다(시즌 전환 = 전부 초기화, `season2-plan.md` D16). 방 포인트처럼 정산해서 다음 시즌 시작 골드로 줄지는 그때 정한다.

## 경제에 주는 영향

| | 화폐 분리 전 | 분리 후 |
|---|---|---|
| 방 포인트 | 낚시 수익이 계속 흘러 들어옴 → 방 물가 상승 | 낚시에서 안 들어옴. **환전으로 빠져나가기만** → 방 경제 안정 |
| 낚시 화폐 | 방 포인트와 섞여서 따로 측정 불가 | 골드만 따로 측정·조정 가능 |
| 소각 | 낚시 소각이 방 포인트를 줄임 | 낚시 소각은 골드만 줄임. 환전이 **방 포인트 소각처**가 됨 |

> `season2-plan.md` 2번 경제 대책(강화가 주 소각처, 새 수입은 내 낚시 수익의 n%, 하루 상한)은 **전부 골드 기준**으로 그대로 쓴다.
