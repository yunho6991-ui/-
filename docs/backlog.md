## ⭐ 1순위 기준: 복잡하지 않을 것

> 기능을 넣을지 말지는 **이게 게임을 더 복잡하게 만드나?**를 가장 먼저 본다. 아무리 재밌어도 복잡하면 뺀다.

**단순도 표시** (각 항목 체크박스 바로 뒤)
- ✅ **단순** — 플레이어가 새로 외울 게 없다. 자동으로 적용되거나, 보이지 않는 개선이다.
- ⚠️ **조건부** — 새 명령이나 규칙이 하나 생긴다. 아래 질문을 통과하는 형태로 줄여서 넣을 수 있으면 넣는다.
- ❌ **복잡** — 새 자원·새 시스템·여러 단계가 필요하다. 1순위 기준상 **기본은 넣지 않는다**. 정말 원하면 더 단순한 형태로 다시 설계한다.

**복잡한지 판단하는 질문** — 하나라도 "아니요"면 ⚠️ 이하
1. **한 줄 설명**: 카톡 한 줄로 설명되나?
2. **새 명령 0~1개**: 새 명령이 없거나 하나뿐인가? (있는 명령에 붙일 수 있으면 그게 낫다)
3. **새 화폐·아이템 없음**: 포인트·미끼·그물·비늘·정수 말고 새로 세야 할 게 생기지 않나?
4. **혼자서도 됨**: 다른 사람이 뭘 해 줘야만 굴러가는 건 아닌가?
5. **안 해도 손해 없음**: 몰라도 원래대로 낚시하면 손해 보지 않나? (몰라서 손해 보는 기능은 결국 모두가 외워야 한다)
6. **기다림·마감 없음**: "n분 안에 답하세요" 같은 시간 압박이 새로 생기지 않나?

**넣을 때 원칙**
- 기능 하나를 넣으면 **하나를 빼거나 합칠 수 있는지** 같이 본다(Z 항목).
- 새 명령보다 **자동 적용**, 새 아이템보다 **있는 숫자 하나 바꾸기**를 먼저 생각한다.
- 결과 메시지에 붙는 줄은 늘리지 않는다. 늘려야 하면 다른 줄을 줄인다.
