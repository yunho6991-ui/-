# 1부. 기획서 v0.1 (정한 것)

## 1. 개요

카톡 채팅방에서 명령어로 하는 **무협 세계관 생존형 텍스트 RPG**.
목표는 정답을 찾는 게임이 아니라 **매번 다른 인생을 살고, 죽음으로 다음 생에 이어지는 것**. 플레이어마다 무공·인연·사건·사망 원인·전생 유산이 달라 **각자의 무협소설**이 만들어지는 느낌.

**핵심 키워드**: 무협 / 생존 / 랜덤 / 전생 / 성장 / 인연 / 위험 / 예측 불가능성 / 각자의 무협소설

## 2. 핵심 철학

| # | 원칙 | 내용 |
|---|---|---|
| ① | 정답 공략을 어렵게 | 같은 행동이라도 만나는 NPC·사건·전투 상황·보상·위험·사망 여부가 달라진다. **랜덤이 핵심 시스템** |
| ② | 강함 ≠ 안전 | 강해질수록 위험한 곳에 가고 사망 위험도 커진다. 무기 파괴·부상·암기·기습·지형·독·외부 개입·상성·뜻밖의 NPC·특수 이벤트 → **강해도 방심하면 죽는다** |
| ③ | 죽음 = 성장 | 죽으면 대부분 잃지만 깨달음·경험 일부가 다음 생으로. "이번 생에서 최대한 얻고 죽자" |

## 3. 기본 루프

```
캐릭터 생성 → 강호 진입 → 수련/탐험/의뢰/교류 → 랜덤 사건
→ 무공·아이템·인연·명성 획득 → 더 위험한 지역 → 전투·사건
→ 사망 또는 생존 → (사망 시) 전생 정산 → 새 인생 → 유산 일부 계승 → 더 깊은 강호
```

## 4. 캐릭터 생성 — 시작부터 다른 인생

랜덤 요소: 출신 · 재능 · 체질 · 성격 · 초기 능력치 · 초기 무공 · 가족관계 · 초기 인연 · 숨겨진 특성

```
출신 : 몰락한 표국의 자식
재능 : 뛰어난 근력
성격 : 겁이 많음
체질 : 독에 강함
초기 무공 : 표국검
숨겨진 특성 : 알 수 없는 검술의 기억
```

## 5. 랜덤 사건 (핵심)

행동을 고르면 결과는 **지역별 사건 테이블**에서 랜덤으로 정해진다.

- 예) 산 탐험 → 야생동물 · 산적 · 무림인 · 상인 · 은둔 고수 · 비급 · 보물 · 부상자 · 신비한 동굴 · 자연재해 · 독초 · 희귀 NPC · 아무 일 없음 · 특수 이벤트 · 사망 이벤트

| 지역 | 사건 테이블 |
|---|---|
| 산 | 야생동물 · 산적 · 약초 · 은둔 고수 · 동굴 |
| 마을 | 상인 · 주점 · 도박 · 의뢰 · 정보 · 사건 |
| 무림맹 | 문파 · 무림인 · 의뢰 · 경쟁 · 정치 사건 |

## 6. 랜덤은 내 상태에 따라 기운다

| 상태 | 테이블 변화 |
|---|---|
| 거지 출신 | 거지 NPC↑ · 돈 사건↑ · 숨겨진 정보↑ |
| 사냥꾼 출신 | 야생동물 사건↑ · 사냥 성공률↑ · 희귀 재료 |
| 악명 높은 무인 | 현상금 사냥꾼 · 적대 NPC↑ · 특정 세력 관계 악화 |

## 7. 전투

능력치(체력 · 내공 · 공격 · 방어 · 속도 · 명중 · 회피 · 치명 · 독/상태이상 · 무공 숙련) + **전투 중 랜덤 이벤트**.

```
당신의 검이 상대의 암기에 맞았다. [무기 내구도 감소]
상대가 숨겨둔 독침을 사용했다. [독 상태]
갑자기 지나가던 무림인이 전투에 개입했다.
```

## 9. 전생 유산 · 기억

| 유산 | 내용 |
|---|---|
| 깨달음 | 특정 무공·상황에 영구 보너스 |
| 체질 | 상태이상 저항 등 |
| 기억 | 겪은 사건을 다음 생에 더 쉽게 알아봄 |
| 인연 | 전생 NPC와 다시 이어질 가능성 |
| 원한 | 나를 죽인 적과 다시 만남 |
| 칭호 | 특수 패시브 |
| 유품 | 다음 생에 특정 아이템 |
| 혈통 | 아주 드물게 특별한 능력 계승 |

**전생 기억 예**: 1회차 산적에게 사망 → 2회차 같은 곳에서 "이상하게 이 길이 익숙하다"(선택지 열림) → 3회차 전생 검술 일부 기억 → 4회차 전생의 원수를 알아봄 → 여러 생에 걸쳐 강호의 비밀을 알아감.

**다 물려받지 않는다**

| 남을 수 있는 것 | 잃는 것 |
|---|---|
| 일부 깨달음 · 일부 무공 숙련 · 특수 칭호 · 체질 · 전생 기록 · 특정 인연 · 일부 기억 | 돈 · 일반 장비 · 현재 명성 · 문파 지위 · 대부분의 인간관계 · 진행 중 의뢰 · 신체 상태 |

## 10. 강호 · 세력 · NPC

- **지역**: 초반 마을/산/강/작은 문파 → 중반 대도시/유명 문파/무림맹/사파 → 후반 금지구역/마교/고대 유적/북방/황궁 → 최종 천하의 비밀/전설의 영역. 지역마다 사건·NPC 테이블이 다르다.
- **세력**: 정파 · 사파 · 마교 · 세가 · 표국 · 상단 · 황실 · 무림맹 · 비밀 조직. 가입 · 승급 · 탈퇴 · 배신 · 추방 · 적대 · 동맹.
- **NPC 데이터**: 이름 · 성격 · 소속 · 경지 · 관계 · 호감도 · 적대도 · 비밀 · 보유 무공 · 현재 위치 · 플레이어와의 기억. 같은 NPC도 플레이어마다 관계가 다르다.
- **NPC도 움직인다**: 문파 전쟁 · NPC 성장/사망 · 세력 흥망 · 새 고수 · 상단 이동 · 지역 변화. "내가 주인공이 아니라 강호에 사는 한 사람".

## 11. 콘텐츠와 코드 분리

사건 하나 = 데이터 한 줄: 사건 ID · 이름 · 발생 지역 · 발생 조건 · 발생 확률 · 관련 세력 · 관련 NPC · 선행 사건 · 결과 · 보상 · 사망 가능 여부 · 희귀 보상 · 전생 기록 여부. 사건을 추가할 때 핵심 코드는 안 고친다.

## 12. 출시 · 테스트

- 얼리액세스가 아니라 **완성 후 공개**(운영 부담 최소화, 출시 때 충분한 콘텐츠, 구조가 빨리 파악되는 것 방지, 밸런스·오류 한 번에 점검).
- 출시 전 여러 신규 캐릭터로: 정보 없이 · 랜덤 행동 · 극단 행동 · 트롤 · 빠른 성장 · 빠른 사망 · 무공 하나만 · 세력 하나만 · 돈만 · 전투만. **개발자가 아는 정답 기준으로 테스트하지 않는다.**

## 13. 피해야 할 구조

❌ 고정 정답(산 → 동굴 → 비급 → 강해짐) · ❌ 능력치만 높으면 승리 · ❌ 죽으면 아무것도 안 남음 · ❌ 의미 없는 랜덤("꽝") · ❌ 사건 하나 추가에 핵심 코드 수정

## 14. 개발 순서

## 15. 이 게임에만 적용하는 규칙 (확정)

| # | 결정 | 내용 |
|---|---|---|
| W1 | **톤 규칙 예외** | 낚시의 "발랄하게 · 죽음·복수 금지" 규칙은 **이 게임에 적용하지 않는다.** 사망·원한·악연이 핵심. 문체는 담백한 무협소설 |
| W2 | **단순도는 "보이는 건 단순하게, 속은 깊게"** | 낚시의 "명령 0~1개 · 새 화폐·아이템 금지"는 그대로 쓰지 않는다. 대신 명령 수와 화면(메시지 한 장 분량)은 작게 유지 |
| W3 | **시즌제** | 시즌이 바뀌면 **전생 유산·기억·원한·기록까지 전부 초기화.** 한 시즌 안에서만 생이 이어진다. 넘어가는 건 시즌 보상(칭호 등)뿐 — 낚시와 같은 원칙 |
| W4 | 유저끼리 손해 없음 | 원한·적대·약탈은 NPC 상대로만. 유저끼리는 강호 소식·기록 자랑만 |

## 16. 최종 목표

"어디로 가야 효율적이지?"보다 **"이번 생에는 대체 무슨 일이 벌어질까?"**.
죽었을 때 "처음부터 다시네"가 아니라 **"이번 생은 여기까지구나. 다음 생에는 저놈을 반드시 찾아간다."**

# 2부. 검토 메모 (제안)

> 기획 방향은 좋다 — "죽음이 콘텐츠"와 "각자의 무협소설"은 카톡 텍스트에 잘 맞는다. 아래는 카톡 봇으로 만들 때 걸리는 점과 단순화 제안.

## A. 이 저장소 규칙과 부딪히는 것 → **1부 15장으로 확정**(W1~W4)

| 규칙 (`CLAUDE.md`) | 기획서 | 제안 |
|---|---|---|
| 톤은 발랄하게, 죽음·복수 금지 | 사망·원한·혈마가 핵심 | 무협 게임은 **이 규칙에서 뺀다**(죽음이 게임의 중심). 단, 잔혹 묘사는 피하고 담백한 무협소설 문체로 |
| 1순위: 단순하게(명령 0~1개, 새 화폐·아이템 금지) | 능력치 10개 · 세력 9개 · NPC 데이터 11칸 | 낚시용 기준을 그대로 쓰면 게임이 안 된다. 대신 **"화면에 보이는 건 단순하게, 속은 깊게"**로 바꿔 적용(아래 B) |
| 유저끼리 손해 금지 | 원한·적대는 NPC 대상 | 그대로 OK. 유저끼리는 자랑·기록 공유만 |
| 시즌 초기화 | 전생 유산이 영구 | 시즌제를 쓸지 정할 것. 쓰면 유산도 시즌마다 초기화 |

## B. 카톡에서 만들 때 걸리는 점

1. **명령 수**: 행동이 많아도 명령은 적게. 단순화 버전:
   - `1강호` — 처음이면 캐릭터 생성, 아니면 내 상태 + 지금 할 수 있는 행동 번호 목록
   - `1행동 [번호]` — 목록에서 고르기(수련·탐험·의뢰·교류·이동, 사건 중 선택지 모두 번호로)
   - ⚠️ 이름이 기존 봇 명령과 겹치는지 확인
2. **선택지 대기에 시간 제한을 두지 않는다**: 사건 중 선택지가 뜨면 몇 시간 뒤에 답해도 된다(시간 압박 금지). 대신 대기 중엔 다른 행동 불가.
3. **능력치는 보이는 건 4~5개만**: 체력 · 내공 · 무공(공격) · 신법(속도·회피) · 경지. 명중·치명·방어 등은 무공·체질 안에 숨겨서 계산. 메시지 한 장에 다 들어가야 한다.
4. **결과 메시지 길이**: 사건 하나 = 3~6줄. 사망 정산만 예외로 길게(자랑용 캡처 포인트).
5. **방(단체톡)과 개인톡**: 플레이는 개인톡, 방에는 **강호 소식만**(누가 죽었다·전설 무공 획득·NPC 고수 등장). 낚시 일보와 같은 방식.

## C. 재미를 키우는 제안

| 제안 | 내용 | 단순화 |
|---|---|---|
| **생애 기록 → 짧은 전기** | 주요 사건이 기록에 쌓이고, 사망 정산에 3~5줄 "○○전(傳)"으로 묶어 준다. "각자의 무협소설"을 문자 그대로 구현 | 사건 데이터에 `기록문` 한 줄씩만 넣으면 됨 |
| **유산은 고르게** | 사망 시 유산 후보 3개 중 1개를 고른다(전부 주지 않음 → 강해지기만 하는 것 방지, 고르는 재미) | 후보 3개 → 1개 |
| **유산 칸 제한** | 동시에 가질 수 있는 유산 최대 n개. 넘치면 교체 | n = 3~5 |
| **원한의 상대는 NPC로 남는다** | 나를 죽인 NPC가 세계에 계속 존재하고 성장한다. 다음 생에 다시 만날 확률↑ | 사망 원인 NPC id만 저장 |
| **강호 시간은 하루 단위로** | NPC 행동·세력 변화는 하루 한 번 일괄 계산(실시간 X). 서버 부담↓, "어제 무림맹에서…" 소식거리 | 하루 1회 배치 |
| **세계는 공유, 관계는 개인** | NPC 위치·생사·세력은 모든 플레이어 공통, 호감도·기억은 플레이어별 | 데이터 두 층 |
| **방 자랑거리** | 최장 생존 · 최고 경지 · 최다 전생 · 희귀 사망 원인 도감 | 기록만 모으면 됨 |

## D. 범위 · 일정 위험

- Phase 1~3 = 시스템 25개. "완성 후 공개"라면 **완성이 계속 밀릴 위험**이 가장 크다.
- 제안: 공개는 완성 후 그대로 하되, 내부적으로는 **"작은 강호" 한 판**부터 끝까지 만든다.
  - 지역 3개(마을 · 산 · 작은 문파) · 세력 2개 · NPC 10명 · 사건 60개 · 무공 15개 · 유산 10종
  - 이걸로 Phase 4 방식 테스트까지 돌려 보고, 재밌으면 지역·사건을 데이터로만 늘린다(코드 분리 원칙 덕).
- 한 생의 길이 목표를 먼저 정하기: 예) 보통 3~7일(하루 행동 n번 기준). 이게 정해져야 사망 확률·성장 속도를 맞출 수 있다.

## E. 사건 데이터 예시 (11장 구조를 그대로)

```yaml
- id: mountain_bandit_01
  name: 산적의 통행세
  region: 산
  weight: 30            # 기본 확률 가중치
  weight_mod:           # 6장 — 상태에 따라 기울기
    출신=거지: -10
    명성>=50: +20
  require: []           # 선행 사건
  text: "좁은 산길에서 산적 셋이 길을 막는다. \"통행세를 내라!\""
  choices:
    - text: 돈을 낸다
      result: {돈: -30%}
    - text: 싸운다
      result: {battle: bandit_x3}
    - text: 도망친다
      result: {check: 신법, success: 무사, fail: {부상: 경상}}
  death_possible: true
  record: "산길에서 산적 셋을 만났다"     # 생애 기록 한 줄
  memory_key: bandit_mountain            # 10장 — 다음 생에 "익숙한 길" 판정용
```

## F. 정할 것

| 질문 | 메모 |
|---|---|
| 시즌 길이 | 한 시즌에 몇 생쯤 살게 할지와 같이 정한다(예: 시즌 8주 · 한 생 3~7일 → 시즌당 10생 안팎) |
| 시즌 보상 | 최고 경지 · 최장 생존 · 최다 전생 · 희귀 사망 원인 등 기록 칭호 |
| 하루 행동 횟수 · 한 생 길이 목표 | 밸런스 기준점 |
| 낚시·방 포인트와 연결 | 완전 별개 추천(낚시 시스템 분리 방향과 같게) |
| 명령 이름 | `1강호` · `1행동` 겹침 확인 |
| 그림(컴피) 쓸지 | 텍스트 게임이지만 전설 NPC·사망 정산 카드 정도는 그림이 있으면 자랑거리 |
