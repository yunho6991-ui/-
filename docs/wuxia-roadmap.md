# 무협 게임 — 구현 로드맵 (카톡 봇에 붙이기)

> 기획 문서를 **로컬 카톡 봇 코드**로 옮기는 순서. 기존 봇 구조(예전에 본 `kakao.py` · `fishing.py`)에 맞춘다.
> 원칙: ① 낚시 코드와 섞지 않는다(낚시 시스템 분리 — `season2-plan.md` 6장) ② 콘텐츠는 `data/wuxia/*.yaml`, 코드는 엔진만(`wuxia-data.md`) ③ **작은 강호 한 판**을 먼저 끝까지 돌린다.

---

## 0. 기존 봇에서 그대로 쓰는 것

| 기존 | 무협에서 |
|---|---|
| Flask가 카톡 메시지를 받아 명령 모듈로 넘김 | 무협 모듈도 같은 자리에 등록 |
| 명령 모듈 꼴: `handles(cmd, helpless) -> bool` · `dm_handle(payload, cmd, rest, helpless) -> Optional[str]` | **똑같은 꼴**로 `wuxia.handles` · `wuxia.dm_handle` |
| `payload["raw_chat_id"]` = 개인톡 방 | 플레이어 식별 |
| `연결`(개인톡 ↔ 방 멤버 잇기 · `db.fish_link_get`) | **같은 연결을 쓰되, 낚시 이름이 붙은 함수는 공용으로 빼기**(`db.link_get` 등) — 분리 작업의 첫걸음 |
| `kakao.send(chat_id, text)` · `send_image` | 개인톡 답장 · 방에 강호 소식 · 초상 그림 |
| 무슨 말이든 들어오면 밀린 결과부터 보여 주기(낚시 `_overdue`) | 부재 중에 당한 일(유저끼리 싸움 · 반려 사건)을 먼저 보여 줌 |
| 사람별 잠금(`_lock_for`) | 같은 사람이 동시에 두 번 `1행동` 해도 꼬이지 않게 |
| `config.py` 상수 | 무협 상수는 `data/wuxia/world.yaml`로(코드 수정 없이 조정) |

> ⚠️ 먼저 확인: 봇 전체 명령에 `강호` · `행동`이 이미 있는지(있으면 이름 바꾸기).

## 1. 카톡이라서 지킬 것

| 제약 | 대응 |
|---|---|
| 버튼이 없다 | 모든 선택은 **번호**(`1행동 3`). 화면 끝에 `▸ 1 … ▸ 2 …` |
| 긴 메시지는 "전체보기"로 접힌다 | 답장 한 번 **12줄 · 400자 안팎**. 사망 정산 · 일지만 예외 |
| 답이 늦게 와도 된다 | 선택지 대기에 **시간 제한 없음** — 기다리는 선택은 DB에 저장(`wx_pending`) |
| 타이머 · 크론이 불편(Termux) | **게으른 계산**: 행동력 회복 · 세계 하루 배치 · 공유 서막 단계는 "다음에 누가 말을 걸 때" 지난 시간만큼 한꺼번에 계산 |
| 같은 순간 여러 사람이 씀 | sqlite 쓰기는 짧게, 사람별 잠금 + 세계 배치는 전역 잠금 하나 |
| 보내기가 줄을 선다 | 강호 소식(전 방)은 하루 한 번 묶어서(`kakao.send` 줄 부담 줄이기) |

## 2. 파일 구조 (제안)

```
bot/commands/wuxia/
  __init__.py      # handles · dm_handle — 명령을 받아 아래로 넘김
  cmd_gangho.py    # 1강호 (빙의 · 상태 · 무공 · 일지 · 전생 · 소식 · 성향)
  cmd_action.py    # 1행동 [번호]
  data.py          # data/wuxia/*.yaml 읽기 · 캐시 · 처음 한 번 검사
  cond.py          # require 문자열 판정 · weight_mod 계산 (wuxia-data.md 2~3장)
  effect.py        # result 적용 (돈 · 숙련 · 부상 · 호감 · 세계 변수 · 꼬리표 · next …)
  events.py        # 사건 고르기(가중치) · 선택지 화면 · 판정 · 연속 사건
  combat.py        # 전투 전 선택 → 3합 → 생사의 선택 → 결과 (wuxia-combat.md)
  character.py     # 빙의(출신 · 성별 · 생김새 · 성격 · 체질 · 재능 · 특기 굴리기)
  life.py          # 나이 · 행동력 · 경지 · 벽 · 부상 회복
  death.py         # 사망 정산 · 유산 고르기 · 짧은 생 · 다음 빙의
  world.py         # 강호 날짜 · 세계 변수 · 막 넘김 · NPC 하루 행동 · 공유 서막 · 정원
  news.py          # 강호 일보 · 큰 소식
  render.py        # 화면 문장 (wuxia-commands.md 3장 · texts.yaml)
  store.py         # DB 읽고 쓰기 (아래 테이블)
data/wuxia/        # 콘텐츠 (이미 있음)
tools/wuxia_data_check.py   # 데이터 검사 (이미 있음)
tools/wuxia_cli.py          # ★ 카톡 없이 터미널에서 플레이 (M0에 만든다)
```

## 3. DB 테이블 (sqlite)

| 테이블 | 담는 것 |
|---|---|
| `wx_player` | 플레이어(연결된 사람 키) · 지금 생 id · 유산 칸(JSON) · 성향(부재 중) · 고정 출신 사용 기록 |
| `wx_life` | 한 생: 이름 · 성별 · 출신 · 행동 수(나이) · 경지 · 숙련 · 생김새 · 성격 · 체질 · 숨은 특성 · 재능 · 특기 · 무공 · 꼬리표 · 돈 · 부상 · 소속 · 위치 · 별호 · 살아 있나 · 행동력(남은 수 · 마지막 회복 시각) — 자주 안 찾는 건 JSON 한 칸 |
| `wx_pending` | 기다리는 선택: 생 id · 사건 id · 단계 · 보여 준 선택지(JSON) · 만든 시각 |
| `wx_affinity` | 생 id × NPC id → 호감 값 · 기억 몇 줄 |
| `wx_seen` · `wx_record` | 이번 생에 겪은 사건 · 생애 기록(전기) |
| `wx_npc` | NPC 세계 상태: 살아 있나 · 경지 · 위치 · 혼인 상대 |
| `wx_world` | 키/값: 시즌 번호 · 메인 깨어났나 · 강호 날짜 · 막 · 세계 변수 · 시작 단서 수 |
| `wx_slot` | 고정 출신 정원: 출신 id · 쓴 수 · 자리별 주인(NPC/생 id) |
| `wx_cohort` | 공유 서막 무리: 출신 id · 시작 시각 · 단계 · 남은 인원 · 구성원 |
| `wx_relic` | 정원 있는 기연: 기연 id · 주인 생 id(없으면 숨은 곳) |
| `wx_news` · `wx_room` | 강호 소식 쌓기 · 소식 받을 방 목록(W6 방별 끄기) |
| `wx_mail` | 부재 중에 일어난 일(다음에 말 걸면 먼저 보여 줌) |
| `wx_death` | 사망 정산 기록(전생 목록 · 사망 원인 도감) |

- 시즌이 바뀌면(회귀) `wx_world`의 넘어가는 변수만 남기고 전부 비운다(W3).

## 4. `1행동 [번호]` 한 번의 흐름

```
1. 연결 확인(link) → 플레이어 → 지금 생 (없으면 "1강호로 빙의")
2. 게으른 계산: 행동력 회복 · 세계 배치(하루 지났으면) · 공유 서막 단계
3. 밀린 일(wx_mail) 있으면 맨 위에 붙임
4. 기다리는 선택(wx_pending)이 있으면 → 번호로 그 선택 처리 → 5로
   없으면 → 번호 = 행동 메뉴(수련 · 탐험 · 의뢰 · 생업 · 이동 · 치료) → 행동력 −1 → 사건 고르기
5. 사건/전투 처리: 판정 → result 적용 → next 있으면 이어서 → 선택지가 남으면 wx_pending 저장
6. 나이 · 수명 · 사망 확인 → 죽었으면 사망 정산 화면 + 유산 고르기(wx_pending)
7. 저장 → 12줄 이내 화면으로 답장
```

## 5. 단계(마일스톤) — 작은 강호 한 판부터

| 단계 | 만드는 것 | 다 됐다는 기준 |
|---|---|---|
| **M0 뼈대** | `data.py` · `cond.py` · `effect.py` · `store.py` · **`tools/wuxia_cli.py`**(터미널 플레이) | CLI에서 `1강호` → 빈 상태 화면이 나온다. 데이터 검사 통과 |
| **M1 빙의** | `character.py` · `1강호` 상태 화면 | 농부 출신으로 빙의 화면(`wuxia-commands.md` 3장)이 뜬다 |
| **M2 사건 실행기** | `events.py` · `render.py` · `wx_pending` | 농부 서막 1단계 사건 6개가 번호 선택으로 진행된다 |
| **M3 전투** | `combat.py` · 문장 풀 | 산적 습격(서막 2단계)이 3합 전투로 끝나고 부상 · 사망이 난다 |
| **M4 죽음과 다음 생** | `death.py` · 유산 · 짧은 생 | 죽으면 정산 → 유산 고르기 → 새 빙의로 이어진다 |
| **M5 작은 강호** | 청하진 사람 12 · 청하진 사건 20 · 농부 서막 끝까지 · 행동 메뉴 | **혼자 한 생을 처음부터 사망까지** CLI로 플레이 · 내부 테스트 |
| **M6 카톡 연결** | `__init__.py` 등록 · 연결 · 사람별 잠금 · 밀린 일 | 개인톡에서 M5가 그대로 된다 |
| **M7 세계** | `world.py` · 호감도 · NPC 하루 행동 · `news.py` 강호 일보 | 방에 강호 일보가 하루 한 번 뜬다 |
| **M8 다른 출신 · 장소** | 서막 12개 · 시작 장소 13곳 · 무공 · 특성 전부 | 출신 13개로 빙의 · 시작 장소가 흩어진다 |
| **M9 고정 출신 · 공유 서막** | `wx_slot` · `wx_cohort` · 늦게 오면 NPC에 빙의 + 일지 | 혈교 아이 서막에 두 사람이 같은 무리로 들어간다 |
| **M10 메인** | 시작 단서 · 「천기가 흔들린 날」 · 막 넘김 · 막 사건 56 | 시작 사건 → 1막 → … → 7막이 세계 변수대로 흐른다 |
| **M11 유저끼리** | 만남 사건 · 부재 중 성향 · 약탈 · 원한 · 혼인(세계에 한 번) | 두 계정이 서로 정체를 모른 채 싸우고 결과를 나중에 본다 |
| **M12 플레이테스트** | 기획서 12장 방식(정보 없이 · 트롤 · 빠른 사망 · 돈만 · 전투만) | `tools/wuxia_sim.py` 숫자와 실제 숫자 비교 · 조정 |
| **출시** | 시즌 1 시작 | — |

- **M5까지가 "작은 강호 한 판"**. 여기서 재미가 없으면 콘텐츠를 늘리기 전에 고친다.

## 6. `tools/wuxia_cli.py` — 카톡 없이 플레이 (M0)

```
$ python3 tools/wuxia_cli.py --player test1
> 1강호
🌫️ 눈을 뜨니 낯선 몸이다. …
> 1행동 2
…
```
- 가짜 `payload`(`raw_chat_id = "cli:test1"`)를 만들어 `wuxia.dm_handle`을 그대로 부른다 → 카톡 연결 코드와 같은 길.
- `--seed 42`로 랜덤을 고정하면 버그를 다시 볼 수 있다.
- `--fast`: 행동력 무한 · 세계 배치 즉시(테스트용).
